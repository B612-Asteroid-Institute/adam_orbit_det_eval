1. Summary
----------
Both pipelines start from the SAME cleaned merge (merged_looo_results_published.parquet,
already filtered by bias_filter) and apply the SAME publication small-sample cutoff
(n_obs >= 100 AND n_objects >= 20). The 24-station gap is entirely driven by ONE
additional filter inside compute_bias_table that observatory_stats_published does not
apply:

  max_object_mean_chi2 = 50.0     (bias_table.py:609-619)

This object-level filter drops 261 objects whose mean held-out chi² across stations
exceeds 50 — 375,803 rows (~7.3% of input). Those rows reduce the per-station n_obs
and n_objects counts inside compute_bias_table, pushing 24 borderline stations below
the 100/20 cutoff that observatory_stats_published kept.

The row-level companion filter, max_hold_in_reduced_chi2=100.0, drops 0 rows on this
input because bias_filter already applied the same cut upstream — so the row-level
filter contributes nothing. Bootstrap convergence did not drop any station; the
asymmetric difference is one-sided (24 in stats-only, 0 in bias-only) and is fully
explained by the count reduction. This is design-by-divergence, not a missing filter:
publication_hygiene calls compute_observatory_stats with max_hold_in_reduced_chi2=None
on the grounds that the bias_filter has already cleaned the input
(18_apply_publication_hygiene.py:154-158), while compute_bias_table re-applies its
own object-quality cleaning to guard against non-gravitational-force contamination.

The 24-station list is reproducible from the published artifacts using only the inputs
named above; see Section 2.

3. Recommended fix and follow-up
---------------------------------
Not fixed in this bead (the bead scope is read-only against the existing artifacts).
Filed as a sibling for coordinator decision:

  beads_agent_setup-4z8 — "Reconcile divergent publication denominators (544 vs 520)
  between observatory_stats_published and bias_table"

The three plausible options are listed in 4z8's description:
  (a) Apply max_object_mean_chi2 <= 50 inside publication_hygiene so
      observatory_stats_published also returns 520 stations.
  (b) Remove max_object_mean_chi2 from compute_bias_table when run on a
      publication-ready input (both files return to 544).
  (c) Keep the divergence and document the two denominators.

Additional flag for 4z8 (or its own ticket): station N86 lost 1,718 of 1,756 rows
(~98%) and 233 of 246 objects after the object-chi2 filter. That dwarfs every other
station's loss (the next highest is G80 at 61%); whatever objects N86 disproportion-
ately observes are also disproportionately the ones globally flagged. May indicate a
station-specific data issue rather than honest non-grav-force contamination, and is
worth a separate look regardless of which option (a)/(b)/(c) is chosen.
