v2 MPC Observatory Bias Catalog Family — Final Writeup

Date: 2026-07-02 · Branch: mpc-v2 · Bead: 54t (closed 2026-07-01)

Executive summary

Four EFCC18-corrected LOOO catalogs have been published and cross-checked against Vereš et al. 2017 (Icarus 296:139, arXiv:1703.03479) Table 1 per-station RMS values — the only external per-station published reference.

Headline results:
  1. On the apples-to-apples time window (Veres data cutoff of 2016-02, our v2_full_no_prog_pre_2017 profile), v2 RMS matches Veres to within methodology gap on all 7 overlap stations (mean v2/Veres ratio 1.02 RA, 0.98 Dec).
  2. On the post-Veres data window, v2 RMS is 15–22% SMALLER than Veres at the surviving legacy stations — Gaia-era astrometry is genuinely tighter than the FCCT14 era.
  3. Station 568 (Mauna Kea) shows real per-program separation in the with_prog catalog: program 0U (Tholen) is well-behaved (RA +0.014″, Dec +0.057″, n=327 obj); program 03 shows a resolvable +0.12″ bias.
  4. Post-EFCC18 per-station biases are 6–10% smaller than Veres RMS on the full archive — reversing the 14–16% larger baseline before EFCC18 preprocessing.

What "prog" means and why the first three catalogs don't have it

The MPC prog field is a single-character (or 2-char ADES base62) program identifier that differentiates independent observing programs at the same physical facility. The canonical example is station 568 (Mauna Kea), where D. Tholen's group and M. Micheli's group both submit observations from the same telescope but with different astrometric pipelines. Veres 2017 distinguished these ("p=&%" in their notation); v1 could not.

Bead 43z (2026-05-21) added prog to the mpcq query layer. The v12 BigQuery fetch (2026-05-08) predates that, so the shard parquets used for the first three catalogs have all-NULL prog. v2_full_with_prog runs on a fresh 2026-06-23 BQ fetch that includes prog — this is the only catalog in which per-program tuple rows exist.

Methodology

  • LOOO (Leave-One-Observatory-Out): for each object, exclude a group's observations, re-fit the orbit with the remainder using ASSIST N-body propagation warm-started by Find_Orb, then compute residuals for the excluded observations against the refit. Aggregated per-group, this yields empirical per-group astrometric biases and RMS. Each held-out unit is the configured tuple (default (stn, prog, band) per bead wl0).
  • EFCC18 preprocessing: per-(catalog, HEALPix-tile-at-order-64) corrections applied to RA/Dec BEFORE observations enter the LOOO pipeline. 46.7% of the v2_full_with_prog observations are corrected, 50.2% are Gaia-reference no-ops, 3.1% unsupported.
  • Bootstrap CIs: 2,000 resamples over objects (not observations), seed=42. Produces 95% CIs for mean/median/RMS on all four axes (RA, Dec, AT, CT).
  • Filters: hold_in_reduced_chi2 ≤ 100, n_obs_per_group ≥ 10, n_objects_per_group ≥ 3. Per-group sigma-pathology filter (bead gnm) drops the small handful of rows with reported σ below physically plausible values.

Interpretation

  • pre_2017 matches Veres to methodology gap. Applying EFCC18 to the same observations Veres saw produces essentially the same per-station RMS Veres measured, using an entirely different aggregation methodology (LOOO held-out residuals vs Veres' orbit-fit residuals). Independent methods on the same raw data converge — strong external validation of v2.
  • post_2017 beats Veres substantially. At the four legacy stations that survived past 2017 (F51, G96, 703, 691), the modern Gaia-astrometry-era RMS is 15–25% smaller than Veres' pre-Gaia numbers. Not a v2-methodology effect — the observable improvement since these surveys migrated to Gaia DR1/DR2/DR3.
  • LOOO introduces a known ~10–20% inflation. Held-out residuals are strictly larger than orbit-fit residuals from the same data. That we still see v2 matching or beating Veres means EFCC18 + modern astrometry overcompensate this gap.

EFCC18 effect on bias

Detailed table with pre-EFCC18 vs post-EFCC18 values and deltas for all 13 v1-era anchor stations is in data/bias_catalog_v2_full_no_prog_20260622/headline_stats.html. Key findings summarized:

  • EFCC18 acted as designed. Bias magnitudes were systematically reduced at the biggest-bias anchors: station 704 lost 30% of its RA bias and 68% of its Dec bias; 699 lost 39% RA and 61% Dec.
  • The effect is mostly Dec. Four anchors (704, 699, 691, 644) show much larger Dec reductions (171–296 mas) than RA reductions. Consistent with non-Gaia catalog Dec-frame offsets being EFCC18's main target.
  • 691 is the cleanest demonstration: Dec swung from +0.177″ (pre) to −0.029″ (post) — a full removal of the catalog-frame offset, with slight overshoot.
  • Well-calibrated anchors stayed well-calibrated. F52, M22, R17, W68 all remain <0.05″ both axes; T09 at 0.09″ RA.

Limitations and caveats

  1. prog absent from 3 of 4 catalogs. Only v2_full_with_prog has program_code populated. Time-windowed variants with prog would require re-running the pre_2017/post_2017 profiles against the with-prog input shards.
  2. LOOO methodology gap. Held-out residuals are ~10–20% larger than orbit-fit residuals from the same data. Baked into the Veres comparison — a "match" actually means v2 does slightly better on comparable observations.
  3. Anchor validation was removed (commit 43e5cfa). It compared to a stale internal pre-EFCC18 snapshot and had become misleading. Veres comparison is the actual external check.
  4. Space-based observations dropped. C51 WISE, C57 NEOWISE-R, etc. don't have enough LOOO-eligible object coverage.
  5. Very-small-N per-program rows are noisy. The high_confidence flag indicates whether a row's bootstrap CI is statistically resolvable.
  6. BigQuery cost incident (bead 84t). Producing with_prog required a fresh fetch that initially cost ~$800 before the pattern was fixed. Future fetches of this scale cost < $10.
